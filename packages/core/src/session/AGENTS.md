# Session Core

- Keep durable events minimal: record irreducible new facts, not facts derivable by folding ordered history. Enrich projections/read models when consumers need self-contained derived state.
- Keep prompt admission separate from execution. `Session.prompt(...)` durably publishes `session.inbox.enqueued` and inserts a `session_inbox` row before advisory `SessionExecution.wake(sessionID)`, unless `resume:false`. Delivery publishes `session.inbox.delivered`; its projection consumes the inbox row and inserts the visible message in the same transaction. The inbox stores only unconsumed work.
- Reusing a Session ID adopts it. Reusing a user/synthetic inbox item ID is idempotent only for matching Session and type: first admission wins; retries ignore payload/metadata/delivery mode, including after delivery reconciled from the projected message. Cross-session/type reuse fails; control items keep operation-specific conflicts.
- Keep `SessionExecution` process-global and Session-ID based. It owns the process-local coordinator and discovers placement via `SessionStore` and `LocationServiceMap.get(session.location)` only when a drain starts; no layer takes a Session ID. Interrupt active ownership; a known idle/unowned Session is a no-op, but unknown Session is rejected.
- Keep `SessionRunner`, model resolution, tool registry, permissions and filesystem Location-scoped. Omitted `Location.workspaceID` means implicit-local placement; explicit workspace identity is reserved for future placement semantics.
- Each step is one explicit `llm.stream` call continuing from reloaded history; never add an in-memory tool loop. Keep drains process-local until clustering. Same-session resumes join/coalesce; different sessions run concurrently. Write-ahead claims are restart-recovery markers: terminal completion/failure/user interruption release them; shutdown interruption/process death preserve them. Recovery resumes claimed top-level Sessions with durable per-execution attempt accounting. Claims are not clustered ownership, fencing or exactly-once guarantees.
- Delivery vocabulary is explicit: prompts steer by default. At safe boundaries steered compaction takes priority up to the first steered move; other steers retain order. At idle, steers precede exactly one queued delivery before reevaluation. Inbox items may be cancelled/changed between queue and steer. Promoting new user input resets the selected agent's step allowance; a steer batch resets once.
- One step is one logical LLM call whose durable record covers the model-visible span. Do not write “provider turn” or call one step a “turn”; reserve “turn” for a future whole assistant turn. Keep event replay ownership separate from Session execution ownership.
